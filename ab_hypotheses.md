# A/B Test Hypotheses — Neobank KYC Funnel

> Generated by `05_ab_test.py`

---

## Background

Funnel analysis revealed that ~40 % of users who start KYC never finish it.
The two highest-impact friction points are:

1. **Document rejection at PAN submission** — ~8 % rejection rate; many
   users who receive a rejection do not retry, creating invisible drop-off.
2. **Selfie step abandonment on Android** — Android users take ~2× longer
   on the selfie step and have measurably higher abandonment than iOS users,
   suggesting the step flow is unclear on that platform.

---

## Hypothesis 1 — Real-Time Field Validation

### What we're changing
Replace the current on-submit validation (users only see errors after
clicking **Submit**) with inline real-time validation that checks each
field as the user types — format, length, and checksum where applicable.

### Primary metric
**KYC document rejection rate** (target: 8 % → 3 %).
Secondary metric: overall KYC completion rate (+8 pp expected).

### Expected effect
| | Control | Treatment |
|---|---|---|
| Doc rejection rate | 8.0 % | ~3.0 % |
| KYC completion rate | ~50 % | ~58 % |

### Randomisation
Split by `user_id` hash modulo 2.  
Assign users at the moment they **enter the KYC flow** (not at signup) so
that the experience is consistent within a session.

### Significance & power
- Significance level (α): **0.05** (two-tailed)
- Statistical power: **80 %**
- Minimum detectable effect (MDE): **5 pp** (8 % → 3 %)
- **Required sample size: 326 users per group**
- Estimated run time: **~2 weeks** at current KYC-entry volume

### How long to run it
Run for at least 2 weeks **or** until each group reaches
326 KYC-entry events, whichever comes later. Do not stop early
based on interim results (no peeking) — this inflates the false-positive rate.

## Hypothesis 2 — Step-by-Step Progress Indicator (Android)

### What we're changing
Add a **visual progress bar** ("Step 2 of 3") and a three-frame explainer
(illustrated instructions: position face, hold steady, tap capture) to the
selfie step — for Android users only, since iOS has a native camera flow
that is already familiar.

### Primary metric
**KYC selfie-step completion rate on Android** (target: +10 pp).
Secondary metric: overall KYC completion rate on Android.

### Expected effect
| | Control (Android) | Treatment (Android) |
|---|---|---|
| Selfie completion rate | ~50 % | ~60 % |

### Randomisation
Split Android users 50/50 by `user_id` hash modulo 2.
Assign at KYC start so the whole KYC journey is consistent per user.
iOS and Web users are **not** part of this test.

### Significance & power
- Significance level (α): **0.05** (two-tailed)
- Statistical power: **80 %**
- Minimum detectable effect (MDE): **10 pp** (50 % → 60 %)
- **Required sample size: 388 Android users per group**
- Estimated run time: **~3 weeks** at current Android KYC volume

### How long to run it
Run for at least 3 weeks or until each group reaches
388 Android KYC-entry events.

## Guardrail metrics (both tests)

Track these to make sure the treatment doesn't cause unexpected harm:

| Metric | Alert threshold |
|---|---|
| Session abandonment rate | > +3 pp vs control |
| Support ticket rate | > +1 pp vs control |
| Time to complete KYC (median) | > +30 s vs control |

---

## Decision criteria

Declare a winner only if **all** of the following hold:
- p-value < 0.05 on the primary metric
- 95 % CI on the lift does not contain 0
- No guardrail metric breached
